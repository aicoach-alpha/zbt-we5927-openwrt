# WE5927 Wi-Fi AP disappearance — evidence and release gate (2026-11-17)

Status: source diagnosis and UI truthfulness fix only. No physical recovery or firmware flashing.

## Actual router evidence (manual root shell; 2026-11-17)

- Board `zbtlink,zbt-we5927`, MT7628AN; OpenWrt 25.12.5, kernel 6.12.94, mt7603e loaded.
- `radio0.up=true`, `pending=false`; radio and primary AP UCI `disabled=0`; guest AP `disabled=1`.
- PHY `/sys/class/ieee80211/phy0` present but no Wi-Fi netdev in `/sys/class/net`.
- `ubus list 'hostapd.*'` empty. hostapd PID and rpcd PID exist and were in S (interruptible sleep), not D.
- Current mt7603 debugfs counters TX hang, DMA stuck, Beacon stuck, RX PSE busy stuck, MCU hang, PSE reset failed all **0**. A zero reading **does not rule out** a previous event or user-space teardown.
- Boot kernel ring shows `phy0-ap0` created repeatedly, removed and re-created, then final visible `(unregistering)` at uptime 1139 seconds; no later AP netdev visible at sample time.
- Guardian repeatedly logged `AP runtime unavailable` roughly every 90 seconds, obscuring historical boot context in bounded system logs.
- LTE RNDIS route and DNS were functional on the earlier sample; do not interrupt them to diagnose Wi-Fi.

## Latest corroboration from live router (2026-11-17 ~13:14 WIB)

- Netifd still lists `default_radio0` and `phy0-ap0` under `radio0.interfaces[*]`, while prior kernel enumeration `/sys/class/net` shows only `br-lan eth0 eth0.1 eth0.2 lo usb0`; its interface list is stale, not proof of a live AP.
- AP UCI security is `sae-mixed`, radio band `2g`, HT20. The pasted output for channel/country was interleaved with shell command echo; **do not conclude an invalid channel/country** without fresh one-line reads.
- `/var/run/hostapd-phy0.conf` plus .prev and PSK/SAE files still exist, even while `ubus list 'hostapd.*'` is empty. File existence cannot prove hostapd is controlling a running AP.
- Generic VeCI UI previously treated netifd `radio0.up=true` and its stale ifname as `AP configured · beacon unverified`. This candidate adds authenticated `veci.wifiRuntimeEvidence` backed by actual kernel sysfs netdev presence and bounded hostapd RPC status; on missing sysfs netdev, it reports **AP interface missing**. Older backend returns **AP status unverified** instead of a false success.
- New evidence collector never calls `iw`, restarts the radio or probes the modem. Its status still does not prove external beacon visibility (requires independent Wi-Fi scan).

## What the evidence does and does not prove

Confirmed: the AP interface did not exist at inspection time, even though netifd radio status said up. **Root cause remains unproven.** Candidate paths: netifd/hostapd configuration teardown, wireless reload or optional guest-service side effect, kernel mac80211/mt7603 interface recreation failure. Do not assert deadlock from `phy0` alone. An OpenWrt issue on hostapd jail exists, but this router's `up=true,pending=false` differs from that report's `up=false,pending=true`; do not disable the jail as an untested workaround.

## Implemented source changes

- Dynamic hostapd object discovery and kernel Wi-Fi netdev check in observe-only Guardian.
- Distinct `reason=wifi_netdev_missing|hostapd_rpc_missing|radio_not_up|phy_missing` in tmpfs health state.
- Log repeated failure only on the first incident / reason change, rather than every poll interval.
- VeCI Wi-Fi UI never marks an enabled UCI SSID as `Broadcasting` just because radio0 up is reported. Disabled, AP unavailable, and AP configured/beacon unverified are distinct.
- Offline regression tests in both generic VeCI and embedded firmware source. None of these claims Wi-Fi has been physically repaired.

## Release and physical UAT

1. Preserve current LAN/LTE, config backup and signed recovery image; no `wifi reload/up/down`, rmmod/modprobe, network restart or flash from remote SSH while mt7603 recovery safety remains unverified.
2. On the next *authorized maintenance* reboot, record early logread/hostapd/netifd events from boot through interface loss on a wired computer. Never copy Wi-Fi keys, IMEI, ICCID or SMS to logs.
3. Check `/sys/class/net/*/phy80211`, live `hostapd.*` status, netifd radio state and mt7603 counters before making any intervention.
4. If AP remains missing, distinguish a hostapd configuration rejection from a kernel failure using the first teardown reason; do not select driver patch merely from a missing interface.
5. Require signed exact-board image, verify with `sysupgrade -T`, backup/recovery, independent SSID beacon scans, multi-device connection, LTE/SMS/dual-SIM regression and long-window UAT before deployment.

No-go for firmware flash until those gates pass.
